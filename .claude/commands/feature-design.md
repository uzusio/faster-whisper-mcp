# 設計スキル（faster-whisper-mcp）

$ARGUMENTS を実装するための設計を行う。

## 実行フロー

### 1. 事前調査（必須）

以下を順番に確認：

1. `CLAUDE.md` - プロジェクト全体の基本方針
2. 関連する既存コードを読む

### 2. アーキテクチャの理解

このプロジェクトの構成：

| ファイル | 役割 | 変更頻度 |
|----------|------|----------|
| `main.py` | CLIエントリーポイント（argparse） | CLIオプション追加時 |
| `mcp_server.py` | MCPサーバ（FastMCP） | MCPツール追加・変更時 |
| `genSrt.py` | 音声認識・SRT生成のコアロジック | 認識処理の変更時 |
| `translator.py` | 翻訳処理（LangChain + OpenAI） | 翻訳機能変更時 |
| `whisper_manager.py` | Whisperモデルの読み込み・管理 | モデル管理変更時 |
| `initial_prompt.txt` | デフォルトの用語補正プロンプト | 用語追加時 |

### 3. 類似機能の探索

以下を調査し、実装パターンを理解する：

- 今回の機能と類似した既存実装を探す
- 既存コードの設計パターンを確認
- 使える既存ユーティリティを洗い出す

### 4. 影響範囲の分析

変更が必要なファイルを特定する。このプロジェクトでは以下のパターンが多い：

- **新しいパラメータ追加**: `genSrt.py`（コア処理） → `main.py`（CLIオプション） → `mcp_server.py`（MCPパラメータ）の3箇所
- **認識処理の変更**: `genSrt.py` のみ
- **新しいMCPツール追加**: `mcp_server.py` のみ
- **モデル管理の変更**: `whisper_manager.py` → 利用箇所

## 設計原則

### CLI / MCP の一貫性

新しい機能は原則として CLI と MCP の両方で提供する：

- `main.py` に argparse オプションを追加
- `mcp_server.py` の該当ツールにパラメータを追加
- 共通のコアロジックは `genSrt.py` に実装

### デフォルト値は精度重視

パラメータのデフォルト値は速度よりも精度を優先する：

- モデル: `large-v3`
- デバイス: `cuda`
- temperature: `0.0`
- VADフィルタ: 有効

### initial_prompt の扱い

- `initial_prompt.txt` のベース内容は常に読み込まれる
- ユーザー指定の追加プロンプトはベースに追記される（上書きではない）

## 環境要件チェック

設計時に確認：

- Python 3.11 互換か
- CUDA 12.x + cuDNN 9 で動作するか
- CPU フォールバックは必要か
- 新しい依存パッケージが必要な場合、`pyproject.toml` への追加が必要
